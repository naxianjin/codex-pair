# apinebula 接入与审核

本技能接受官方 Codex CLI 中用户已有的 `modelProvider=apinebula` 配置，保留原模型、认证、权限及窗口。身份以当前线程的 API 元数据为准；目录名和窗口标题不能证明身份。技能不新增接口或索取、复制密钥。

用户于2026-11-05明确选择“允许第三方审核替代官方审核，记录为第三方”。因此 apinebula 的持久 `gpt-*` 独立会话可承担固定阶段、恢复及辅助池审核，并满足原来的审核门槛。该例外覆盖本技能旧说明中的仅官方服务要求，包括 DeepSeek、wokey 成果的审核；不授予普通开发、审批或发布权限。

审核会话必须沿用所选来源配置的实际提供方与模型，不强制切到 openai。审核者与作者不能是同一会话；已有贡献链、候选摘要、需求版本、运行代次、执行和工具证据继续核验。提供方改变后旧绑定失效。严格 `official_identity` 入口仍拒绝 apinebula，防止第三方来源被认定为官方身份。

旧审核器状态及阶段报告保存 `modelProvider`/`reviewer_provider` 与 `review_service`；辅助报告证据也由控制器写入这两个来源字段。apinebula 使用 `review_service=third_party`，OpenAI 使用 `openai_official`。模型自行填写来源不能覆盖控制器记录。

第三方没有可用的官方账号与额度证据时，不调用官方 account 接口，额度保持未知；按现有负担均衡调度，不参与20个百分点比较。共享额度池仅按本地配置保守分组，不能据此推断两个目录是否共用第三方套餐。

已运行的隔离回归及未验证范围见 CHANGELOG.md。本轮代码和安装验证不代表真实 apinebula 双窗口握手、模型审核或任务交付已经通过。旧桥不会因安装更新自动加载新版，须核实旧执行后按正规入口切换。
