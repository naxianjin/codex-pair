# Windows 隔离环境探针记录（2026-11-02）

本轮按用户授权配置受限执行环境，并运行专用环境探针。候选项目的 210 项行为规格执行数仍为 0，未导入候选模块、运行候选安装器或打包器，也未修改已安装 skill、真实账号或协作状态。以下结果只覆盖探针，不代表指南第 25.8 节整体通过或正式项目验收通过。

## 环境与执行范围

沿用 E 盘专用 Hyper-V Windows 客体。客体没有虚拟网卡；工具来自本机已有发行文件，经归档及传输摘要核对后复制，不下载工具、不经过 v2rayN，也不复制宿主登录资料。实际版本为 Python 3.12.14、Git 2.55.0.windows.5、Node 24.20.0。

在客体内使用非管理员 PairWorker、受限令牌、独立桌面、14 项环境变量白名单和只读工具目录。探针启动时挂入 Job Object 后才继续运行。当前入口只接受预定义探针，所有回执均为 `CandidateExecutionAllowed=false`，尚不支持项目任意任务。

配置上限：同时 8 个进程、单进程 384 MiB / 合计 512 MiB 内存、128 MiB scratch 卷及 64 MiB NTFS 用户配额。CPU 时间请求上限为 8 秒，Windows 按周期检查，实际会超出；另有客体墙钟超时和宿主超时关闭虚拟机的保护。

## 实际检查结果

| 检查 | 实际结果及限制 |
| --- | --- |
| 写入边界与假凭据 | 9 个目录/工具文件写入尝试被拒绝；假私人文件读取被拒绝；scratch 可写。没有读取真实凭据 |
| 网络 | 外部测试地址连接失败，错误 10051；客体本地回环发送和回复成功 |
| 内存 | 分配到 352 MiB 后出现 MemoryError；合计内存上限已配置，但没有单独完成合计耗尽探针 |
| 磁盘 | 普通文件写入 66,060,288 字节后返回 errno 28 |
| 稀疏文件 | 初始仅限制卷容量时，1 GiB 逻辑文件仍可创建；启用配额并修正可写夹具所有者后，扩展被拒绝，逻辑长度为 0 |
| 进程 | 仅能建立 7 个子进程，加主进程达到同时 8 个限制；3 秒超时后 ActiveProcesses=0。主进程退出码 0 不代表整项成功，回执 TimedOut=true |
| 墙钟与 CPU | 2 秒墙钟探针以 124 退出、无剩余进程；最终 CPU 探针约 9.97 秒终止，CPUSeconds=9.828125，退出 0xC0000044。较早 CPU 探针约 14 秒终止，不能宣称精确 8 秒截止 |
| 证据文件 | 硬链接、符号链接、目录联接、超过 1 MiB 的文件及路径穿越均拒绝；根目录换成联接也被拒绝并恢复 |
| 控制器崩溃 | 单独终止持有 Job 的控制器，监督进程仍运行，已启动的探针子进程数从 1 变为 0 |
| 宿主超时 | 模拟控制调用卡住后，宿主关闭虚拟机，不接收结果；保留未确认记录，核实关机后归档，没有重放任务 |
| 未确认门禁 | 有待核对记录时拒绝启动下一次探针 |
| 最终复核 | 最后 8 次回执源文件摘要一致，证据摘要匹配，ActiveProcesses 均为 0；临时计划任务与机器保护密码临时文件均不存在 |

证据读取以执行前打开的 scratch 根目录句柄为锚点，只允许平铺 JSON 文件名，拒绝链接及非普通文件，并核对同一句柄读取前后的身份、长度和修改时间。宿主使用独占新建目标，写入后从同一句柄读回计算摘要。变更中的文件拒绝逻辑已编码，但未专门运行并发修改探针。

## 已修正的环境问题

受限 Python 最初以 `0xC0000142`（DLL initialization failed，DLL 初始化失败）退出。补齐令牌中原始 Logon SID 和所需限制组后，Python 探针启动成功，写入拒绝检查仍通过。用于定位问题的不受限启动对照只证明运行时可启动，不计入隔离通过结果，也不进入可复用探针归档。

小容量卷不能单独约束稀疏文件的逻辑长度，因此增加 NTFS 配额。管理员拥有的可写夹具可能逃逸 PairWorker 配额，已将本轮明确的可写夹具设为 PairWorker 所有。管理员组配额设置返回 `Error 5: Access is denied`，未记为成功；后续任务导入仍需确保可写文件所有权正确。
