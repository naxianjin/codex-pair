# 宿主校验回执接线缺口

记录日期：2026-11-02。状态：**待实现、待真实验证**。

本记录说明 Cloudflare 轨道从辅助报告到正式结算之间缺少的生产链路。Windows 句柄式输入读取器和离线回归已经提供局部验证证据，但不能代替原官方会话的工具回执、当前执行绑定或父阶段的独立审核。本记录没有实现新入口，也没有授权静态辅助会话执行命令。

## 已核实的调用链

1. `register_audit()`（`scripts/pair_auxiliary.py`，本地候选） 登记父审计、固定阶段、必需轨道、覆盖单元和贡献上下文。候选的 `contract_digest` 由 `requirements_version`、阶段的 `coordinator_acceptance`、`coordinator_required_checks` 计算。
2. 同文件的 `queue_auxiliary()` 登记辅助任务及 `requires_dynamic`，`reserve_auxiliary()` 创建带租约、会话代次和候选/契约摘要的准确执行。
3. `begin_execution()`（`scripts/pair_auxiliary_runtime.py`，本地候选） 对 `requires_dynamic=True` 返回 `hyperv_environment_unverified`；同文件控制器调度循环也跳过动态任务。静态路径禁用 shell 等执行工具，仅开放固定候选和审核资产的分页读取、交接工具。
4. `finish_auxiliary()` 调用同文件的 `finish_execution()`。后者先由 `_observe_execution()` 查询该辅助执行自身的官方会话和准确回合，核对身份、终态、工具终态、生产者及 rollout 来源。报告必须与 `_terminal_review_report()` 从该官方终态取得的报告一致。
5. `adapt_report()`（`scripts/pair_audit_adapter.py`，本地候选） 校验上下文、覆盖和报告结构。Cloudflare 轨道始终生成两项 `required_validations`：`validate-findings.cjs` 和 `validate-coverage-ledger.cjs`。每项包含校验器路径/摘要、输入字段/摘要及三个 `reader_assets` 摘要；findings 另含 schema 路径/摘要。
6. `finish_execution()` 用辅助回合中的真实工具回执匹配阶段的必要检查，但只要 `required_validations` 非空，就无条件将 `formal_checks_verified` 设为 `False`。这里尚未查询或验收宿主运行完整 CJS 校验的证据。
7. `_save_auxiliary_report()` 原样保存 `validation`，因此 `reader_assets` 没有在存储途中丢失。`settle_audit()` 再检查覆盖、独立性、必要正式回执等条件；缺正式回执时保留 `formal_receipts_missing`，不能放行父阶段。

还有一个后续接线必须处理的生命周期条件：`finish_execution()` 对已经完成且报告摘要相同的执行直接返回重复提交，`_save_auxiliary_report()` 也不会改写已固定的原报告。若宿主校验发生在报告保存之后，需要另外保存绑定原报告的补充校验事实，不能反复提交同一报告，或把旧记录中的 `False` 直接改成 `True`。

## 为什么不能只删掉恒 False

静态辅助正常运行时没有执行 CJS 的工具权限，其终态不应凭空出现这类工具回执。当前来源查询又只覆盖辅助会话自身，未登记宿主 A 的校验执行与该辅助报告之间的关系。

本机专用 Hyper-V 执行器目前登记的是离线 unittest 模块入口。它的 JSON 回执和测试结果没有自动成为 skill 的官方工具证据，也不能通过传入 `validation_records`、布尔值或一条看起来相同的命令来追认。缺少的是受管验证入口及其证据关联，不能在结算函数里补一个乐观判断。

`pair_control_runtime.py`（`scripts/pair_control_runtime.py`，本地候选） 中现有恢复证据适配器对隔离能力明确返回 `isolation_verified=False`。`VerifiedRecoveryEvidence`（`scripts/pair_recovery.py`，本地候选） 是可信适配器返回值的类型和绑定约束，不是允许 CLI 用户构造通过证明的入口，也不能替代尚不存在的宿主隔离适配器。

## 可以复用的能力与适用边界

| 现有能力 | 可复用部分 | 不能直接承担的部分 |
| --- | --- | --- |
| `AppServer(..., metadata_only=True)`、`read_thread()`、`turns(..., items_view='full')` | 只读查询原官方会话、准确回合及完整工具项 | 不能从会话名称推定身份，也不能用辅助会话身份代替宿主 A 身份 |
| `file_identity()`、`verify_launch()`、`producer_context()`（`scripts/pair_producer.py`，本地候选） | 文件/进程身份、支持的生产者版本及准确绑定 | CLI 来源证明不自动证明 Node、PowerShell、.NET 或自定义执行器来源 |
| `rollout_command_items()`、`command_receipt()`、`command_matches()`（`scripts/pair_transport.py`，本地候选） | 原会话持久记录、终态字段、版本对应的精确命令匹配 | 不把模型文字或输出 JSON 解释为工具成功；宿主回执只证明宿主命令，客体子命令不会自动取得官方工具项 ID |
| `receipt_items()`（`scripts/pair_review_receipts.py`，本地候选） | 合并并核对 API 与 rollout；严格版本要求 raw/display 双源一致，冲突项拒绝 | 它需要调用方先取得正确会话的真实来源，不能用调用者提供的列表代替来源查询 |
| 同文件的 `current_binding()`、`verified_turn()`、`read_receipts()` | 既有固定审核的只读查询和前后绑定复核方式 | 当前依赖 `reviewer_runtime` 及运行中的固定阶段；不是任意宿主 A 回合或已完成辅助报告的通用查询接口 |
| `_binding()`、`_context()`、`_auxiliary_candidate()`、`_auxiliary_execution()` | 已有候选、契约、辅助执行、租约与会话代次核对 | 宿主验证执行及其控制代次仍需单独绑定 |
| `load_assets()`、`required_validations` | 发行清单、上游锁定、validator/schema/reader 摘要与准确载荷摘要 | 文件存在或摘要正确不证明完整校验器已运行 |
| 本机受限执行器的句柄提证与终态控制 | 只读输入、任务临时盘、资源约束、全部子进程终止后的受控提取 | 还需固定 validator 入口及正式契约；现有 unittest 回执不能直接升级成生产校验回执 |

三个 Windows reader 资产已经列入发行清单和打包必需项；安装器按清单完整复制并复核。PowerShell 使用进程级 `RemoteSigned` 策略启动 C# 读取辅助器，没有修改全局执行策略。正式工具链身份仍需涵盖 Node、系统 PowerShell 和 .NET/编译环境，不能只登记 `.cjs` 文件摘要。

## 下一工作项的契约内容

下面是接线所需的信息集合，**不是已实现的接口字段或数据库迁移**。具体字段名和存储方式应在实现时复用现有结构；不能只接收一份用户 JSON 就认为这些信息已被验证。

| 信息组 | 必须绑定和核对的内容 |
| --- | --- |
| 审计对象 | pair、父审计、阶段、辅助任务、辅助执行、准确原报告摘要、轨道、覆盖单元、候选摘要、需求版本、原检查契约摘要 |
| 原辅助来源 | 原会话/回合、执行代次、生产者证明、原报告与官方终态的一致性；保留原报告摘要及脱敏后的保存摘要，不混用两者 |
| 宿主执行主体 | 登记的宿主成员、原官方会话、绑定版本、账号配置归属、实际模型/提供方、CLI 生产者身份、准确宿主 turn/item；查询时复核，不能由窗口标题或目录名认定 |
| 许可与控制 | 当前控制代次、授权版本、允许的固定校验操作、领取/执行身份；恢复接续需引用原有许可和对账规则，不继承失效授权 |
| 精确执行契约 | 宿主真实执行器的绝对路径及摘要、精确 argv/展示命令/cwd、输入快照、VM 身份、隔离边界和资源上限；禁止把客体子命令包装成虚构的宿主官方工具项 |
| 校验依赖 | Node 身份；系统 PowerShell 和 .NET/编译环境身份；两个完整 validator、三个 reader 资产以及适用 schema 的准确摘要 |
| 校验输入 | 从已固定报告导出的 findings、coverage_ledger，与适配器登记的载荷摘要逐项一致；同时绑定实际传入字节摘要及明确的序列化格式，不接受另行提交的等名文件 |
| 执行与提取事实 | 宿主官方工具项的终态和退出码、准确隔离运行 ID、客体完整校验结果、全部子进程终态、输入/工具保持不变、按白名单提取的结果摘要及来源 |
| 补充校验记录 | 与原报告/候选/契约/辅助代次不可变关联，重复提交幂等；来源冲突或查询结果未知时保留待核对，不重放原操作 |

建议按以下顺序接通：

1. 先确认原宿主官方会话，以及可登记、可查询的固定 validator 执行入口。保留静态辅助禁执行的现有权限边界。
2. 在执行前固定上述契约，将报告载荷和校验资产交给可信隔离执行器；禁止校验过程中下载或替换依赖。
3. 校验完成后只提交引用。可信结算入口重新查询官方会话及 rollout，核对宿主精确命令、来源和终态，并验收绑定同次运行的受控提取结果。
4. 在事务内重新核对报告、候选、契约、绑定和控制代次，将补充校验事实可靠保存。然后由父结算继续核对全部必要检查、覆盖和独立性；两个 CJS 成功并不单独构成父阶段通过。

如果保存原报告后发生了新辅助执行、会话交接或候选变化，必须按准确旧执行与新执行的关系处理，不能让迟到的宿主结果写入新执行。暂停期间可以按既有规则保存原执行事实，不能因此发起新校验或自动继续业务。

## 建议补齐的阴性回归

这些用例尚未为该生产接口实现或执行。应测试真实登记、查询和结算实现，仅在官方客户端和客体系统边界使用必要的隔离替身。

| 情况 | 必须观察到的结果 |
| --- | --- |
| 直接传入 `passed=true`、自报回执、报告中的 `validation_records` | 不授予正式校验通过，不触发父阶段放行 |
| 没有宿主原会话、API 查询失败、rollout 缺失或来源冲突 | 保留 `needs_validation` 或准确未确认状态；不猜工具项 ID、不重跑原命令 |
| 宿主来自另一个 pair、账号配置、会话、绑定版本、回合或执行代次 | 拒绝关联，不能靠相同命令文字借用回执 |
| 精确 argv、换行、引号、cwd 不同，或同一检查匹配多个回执 | 不按“相近命令”接受，不任选其中一条 |
| validator 正确但 reader、schema、Node、PowerShell/.NET 或执行器身份不符 | 不能通过；完整依赖身份必须逐项匹配 |
| findings/coverage_ledger 少一项、摘要不符、序列化未登记、另传同名文件 | 不能用局部校验或另一个文件替代固定报告载荷 |
| 命令退出码非零、工具或子进程仍活动、超时、取消、结果未知 | 不释放必要验证义务，不把回合结束视为全部操作成功 |
| 证据文件是链接、非普通文件、超限、读取时被修改或来源不明 | 不接收为有效证据，不退化为普通路径复制 |
| 查询前后候选、需求、检查契约、报告或控制代次改变 | 本次结果不得作用于变化后的对象 |
| 原报告已固定后重复提交，或相同验证标识携带不同事实 | 相同请求幂等，冲突拒绝；不得改写原始报告或清除旧失败 |
| 原执行在暂停期间完成或迟到 | 允许范围内只保存原事实，不启动新工具、模型或下游业务 |
| 作者/发现者冒充独立验证者，或覆盖、必要检查仍缺失 | 即使 CJS 校验成功，父阶段仍不得通过 |

还需一个正向集成用例：通过原宿主官方会话运行固定隔离 validator 入口，查询并关联同一次运行的真实工具回执，核对全部输入、依赖和终态，再验证父阶段仍受其余独立审核与覆盖条件约束。离线替身用例通过只能证明接线逻辑，不能将这一项登记为真实验收通过。

## 当前停止位置

保留现有 `required_validations` 门禁、原始报告和失败记录。本轮没有新增宿主验证入口、没有放宽辅助权限、没有迁移活动状态库，也没有为缺失回执制造正向证明。下一步先完成已暴露离线回归的修复与复测；待原宿主官方会话和可信 validator 入口确定后，再实施这里登记的独立工作项。
