# wokey 提供方边界

本页只描述官方 Codex CLI 中已经由用户配置好的 `wokey` 提供方。技能不配置接口地址、模型、API Key 或认证，也不把 `wokey` 配置目录当作账号证明。

加入和交接时，必须从当前原窗口的 `thread/read` 取得 `modelProvider=wokey` 和模型名，并按会话 UUID、cwd、配置目录和 Git 身份绑定。不能用窗口标题、目录名、模型名或历史绑定猜测窗口；新一轮由第一个调用 skill 的窗口成为 A，只有显式恢复才沿用旧角色。

`wokey` 不提供本 skill 所需的官方 `account/read` 与 `account/rateLimits/read` 证据。额度状态保存为 `unknown`，不参与 20 个百分点的额度比较，也不因额度未知暂停或转移已开始的任务；调度回退到可比工作量和当前负担均衡。若另一成员是 OpenAI 且额度可比，仍可使用 OpenAI 的真实额度；不可把未知的 wokey 状态当成百分比。

`wokey` 成员可以开发、提问、交付和接收依赖，但其贡献必须保留实际 provider/model 来源。任何由 wokey 实质完成的成果，在整合、发布或供后续任务使用前，仍需要独立核验的 OpenAI 官方 GPT 审核；wokey 不能担任该审核者，也不能凭模型名 `gpt-*` 获得资格。

当前真实双窗口验收需分别确认：原窗口绑定、双向 queue 通信、模型回合终态、任务交付、读取与整合。隔离单元测试只证明上述边界代码，不代替真实 wokey 服务或原窗口验收。
