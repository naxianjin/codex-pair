## v1.1.3：DeepSeek 原窗口基础可用性

日期：2026-10-16。官方 Codex CLI 0.163.0；OpenAI A 与用户接受邀请的 DeepSeek B 保留各自有效 CODEX_HOME。本记录只公开脱敏结论，真实会话 UUID、本机路径、数据库、完整命令日志及安装回执留在本机，不上传或打包。

已核对的真实流程：

1. 当前窗口经官方元数据登记为新 A，用户所选 DeepSeek 窗口自行 accept；没有冒用旧 A 或旧 B 的 UUID、令牌。旧轮停止派发且保留未完成状态，没有伪造旧任务完成。
2. 原窗口关联 question/reply、claim/complete 和回合终态确认后，communication=verified。
3. B 实际领取独立测试任务，在新的交接目录排他创建 75 字节模拟 JSON；第二个 Python 进程实际回读并断言，两个进程 SHA256 一致。原有 proof 和失败证据保持不变。
4. B 从其自身环境运行技能 CLI status，退出码 0，核对当前成员、任务与通信状态。
5. B 用已有 Python 3.12.13 执行 `-X utf8 -B -m unittest tests.test_deepseek -q` 一次：15 项通过、0 跳过、0 失败、0 错误、退出码 0；原始统计写在 stderr，stdout 为空。A 交叉核对实际工具调用、文件哈希和日志，没有代跑测试。
6. A 完整分页读取并 ack 交付，检查证据后完成结果消息；随后独立规划任务确认 goal_completed=true，两项任务均 completed，停止自动接续。B 续行回合有持久化 task_complete，A 结果回合也已确认完成。

权限边界：最初原窗口为受限沙箱，Python 3.13.9 的临时目录初始化及清理报 30 个权限错误；此失败保留。此次测试中途由用户明确选择 Full access / never，原回合被用户中断后在同一会话核对进度继续；实际写入与单元测试发生在切换后。磁盘配置、运行中回合权限和业务结果分开核对，不把旧 interrupted 当作正常完成，不声称受限沙箱已经通过。

源码改动仅为 Windows 专项模拟测试目录继承现有 ACL，15 个测试方法与断言不变；运行时协议没有新增任务恢复或身份迁移入口。此前讨论后撤回的恢复方案不属于本版。

未验证：DeepSeek×DeepSeek、DeepSeek A×OpenAI B、完整 Git 提交交付/整合矩阵、其他 CLI 版本、受限沙箱下的完整工具能力。此前安装副本未执行本次专项；后续源码回归和安装文件一致性应使用各自实际回执，不能把这 15 项作为全量回归或所有安装目录的实机结果。

## v1.1.2：双向完成检测与安装版验证

日期：2026-10-16。修复非拥有者 API 返回的历史回合终态缺失导致共享工作区持续阻塞的问题。`idle`、`notLoaded`、超时和队列接受回执都不单独作为完成依据；只读官方会话日志中的持久化回合事件作为补充证据，验证账号目录、会话、cwd 和准确 turn_id。最新回合仍在执行时保持阻塞，业务完成仍以 claim/complete 为准。

本轮复用两个已经登记的 OpenAI 官方 CLI 原窗口，没有新建模型会话或重新配对：

1. B 实际执行源码完整回归并交付。
2. A 收到结果后完整读取、确认并收尾；独立阅读任务再核对日志，将确认交给 B。
3. B 收到并确认 A 的交付，随后由已登记依赖启动第二次任务，核对真实双向链路。
4. B 从实际安装目录运行指定测试，检查模块导入来源与文件哈希，交付给 A。
5. A 完整读取结果和证据并确认；阶段结束后自动收到规划任务，以 --goal-complete 结束本验证目标。
6. 本地等待脚本只在全部业务消息和模型回合确认为终态后停止测试桥。最终 goal_completed=true、协作 stopped、桥锁已释放，没有继续生成新任务。

四项新验证任务与相关结果均完成，每条消息实际投递 1 次。该记录包含实际任务信封、领取、交付读取确认及远端终态，不以 accepted 回执代替执行。原始会话标识、数据库、账号目录、私有日志和安装备份只留在项目 .codex-pair/，不公开或打包。

测试统计：

- 源码完整回归：160 项，157 项通过、3 项显式真实环境测试跳过，退出码 0。
- 新增完成检测专项：12 项全部通过，包括 A→B/B→A、重启去重、半行补齐、身份/账号目录边界、损坏记录和 Windows 扩展路径。
- 实际安装目录专项：35 项，34 项通过、1 项显式真实 transport 测试跳过，退出码 0；模块来源确认是安装目录。
- 31 个安装包文件与清单、源码 SHA-256 一致。发布 ZIP 只包含运行文件，按发布包清单另行校验，不将源码测试目录或私有记录加入发行包。

范围：本机当前两个 OpenAI 原窗口已通过本轮接续；本轮没有新增带提交的 Git 整合验证。DeepSeek 双窗口、混合配对、其他 CLI 版本和 relay 降级路径仍不因本轮结果视为通过。历史测试中的失败保留原记录，跳过项不记为通过；不同批次统计不可互换。

两个用户已打开的官方 Codex CLI 原窗口，均使用 OpenAI 官方账号，分别保留不同 CODEX_HOME。测试在项目内独立测试仓库进行，不改业务源码，不创建或整合 Git 提交。

3. A 对结果仅完整读取、确认和收尾，结束回合，不在结果回合登记后续任务或自行发送唤醒消息。
4. 系统自动登记独立规划任务并唤醒 A。A 在该任务中登记依赖第一阶段的第二阶段任务，结束回合。
5. 桥自动唤醒 B，B 读取任务范围、前置交付并确认，仅创建 `stage2.txt`，内容为 `CONTINUATION_STAGE2_OK`。中间没有用户输入“继续”。

结论：本机 OpenAI 原窗口的“结果只收尾，后续由独立任务调度”路径已通过真实两阶段验证，不是文件信箱或队列接受回执替代验证。
