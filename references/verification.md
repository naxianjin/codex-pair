# 自动接续验收记录

日期：2026-10-16。v1.1.1 同步说明与验收结论，运行代码来自 v1.1.0（提交 `506cba3f6b886d79ac794241c759e9de3a81e721`）。本文仅公开脱敏结论，原始数据库、会话标识、账号目录及日志留在本机，不随技能发布。

## 本轮真实原窗口测试

两个用户已打开的官方 Codex CLI 原窗口，均使用 OpenAI 官方账号，分别保留不同 CODEX_HOME。测试在项目内独立测试仓库进行，不改业务源码，不创建或整合 Git 提交。

1. 原窗口完成邀请、关联问答和回执，`communication=verified`。
2. B 完成第一阶段，仅创建 `stage1.txt`，内容为 `CONTINUATION_STAGE1_OK`。
3. A 对结果仅完整读取、确认和收尾，结束回合，不在结果回合登记后续任务或自行发送唤醒消息。
4. 系统自动登记独立规划任务并唤醒 A。A 在该任务中登记依赖第一阶段的第二阶段任务，结束回合。
5. 桥自动唤醒 B，B 读取任务范围、前置交付并确认，仅创建 `stage2.txt`，内容为 `CONTINUATION_STAGE2_OK`。中间没有用户输入“继续”。
6. A 收尾第二次结果后再次由独立规划任务唤醒，核验证据并以 `complete --goal-complete` 结束目标。
7. 等待全部原模型回合结束，再观察 12 秒，无新增任务；停止本测试桥并确认锁释放。

最终：4 个任务（2 个业务任务、2 个规划任务）全部 completed；9 条消息的业务与远端回合均 completed，投递均 accepted，每条实际投递 1 次。`goal_completed=true`，协作 stopped，桥锁未持有。

结论：本机 OpenAI 原窗口的“结果只收尾，后续由独立任务调度”路径已通过真实两阶段验证，不是文件信箱或队列接受回执替代验证。

## 自动化测试与边界

完整回归共 148 项，145 项通过、3 项需要显式开启的真实环境测试默认跳过，退出码 0。真实原窗口测试另按上述步骤执行，不将跳过项记作通过。

- 本轮未重新执行带 Git 提交的交付整合；此前记录不等于本轮重测。
- DeepSeek×DeepSeek、OpenAI×DeepSeek 及反向组合仍待真实双窗口完整验证。
- 其他 CLI 版本、relay 降级路径未在本轮实机重测。
- 自动规划适用于启用窗口流程的新 quota-balanced 轮次：业务任务均 completed/integrated、结果均收尾且没有失败或结果不明消息后才推进。有提交但未整合时等待整合；旧 legacy 轮次不自动改策略。
- 目标完成、暂停、停止或缺少新增授权时，不承诺继续工作。安装同版文件不等于现有会话或旧桥已重新加载。
