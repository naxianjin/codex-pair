# Codex Pair

本分支为四可见窗口开发候选。2026-10-21已修复深路径备份/建树、取消任务终态保护，以及检查点恢复、通知领取和派发中的旧回执误拦；相关增量经原B独立复核，原双窗口恢复通知已真实投递、领取、完成，并确认模型回合终态完成。真实四窗口、隐藏审核及完整故障矩阵仍未验收，不是正式发布。用户已授权将本次最新候选安装到D:/Codex下.codex、.codex-b、.codex-c、.codex-deepseek，明确排除.codex-cc-switch；不推送、不打标签、不创建Release。安装副本与已加载运行实例分别核对，安装成功不代表运行实例自动更新。

先读[命令与输入](references/team-commands.md)，接管测试时读[详细验证交接](references/validation-handoff-four-cli.md)。旧双窗口协议的领取、分页、交付和未知对账仍适用；旧文档“只能两个”“不新建任何模型会话”和9%新轮次默认值仅描述v1.2.1，不能覆盖本轮明确规格。

## 成员与授权边界

原窗口恢复试验或不可换人的工作必须用 assign --pin-member；独立核验必须用 --independent-of 引用被核验任务，不能仅在正文声明。约束检查覆盖调度和交接消费；额度恢复不收回已转交任务。新修复本地328项（325通过、3跳过），原C独立复核及安装/新冻结运行副本验证待完成。

- 默认A/B两个用户已打开的原CLI；C/D使用本轮一次性邀请加入，最多四个可见成员。保留各自账号、提供方、模型、权限和原会话根cwd。
- 唯一允许新增的模型会话是A管理的一个独立隐藏审核CLI；满员共五个模型会话。不用后台exec或另开模型替代可见成员。
- 可见提供方仅OpenAI官方账号或原CLI已配置的DeepSeek；不配置API、不复制Key或认证。隐藏审核者必须从实际官方API核验A的OpenAI GPT账号及模型，复用同一配置与真实额度池，不能凭目录或别名认定。
- A拆任务、答普通问题、审核权限、处理阻塞、整合和发布；其他执行者建议拆分交A。隐藏审核者只读实现、隔离测试、登记原范围阻塞返修，不接普通开发、不统筹、不审批。
- 初始effort参考：两人A30%/B70%；三人A10～20%；四人A10%，其余均衡。按任务、能力、权限、额度和负担调整，不按代码行数硬算。
- A自己的实现用短阶段，在安全边界让出回合：用户停止/撤销/变更 → 权限及阻塞答疑 → 返修交接与必要整合 → 普通实现。

## 当前窗口入口

从用户选定的原窗口执行：

```text
<Python> <本技能>/scripts/pair.py start --project <仓库> --goal <目标> --json
```

使用实际Python3.10+，不用WindowsApps占位程序。A输出完整join_instruction供用户贴给原B；B从自身环境accept，不手填别人的UUID或配置目录。C/D用invite-member返回的join_argv加入，不重新start。相同可见会话同一时刻只参加一轮，其他会话可做别的项目。

新成员先实际验证原会话、提供方、通信和上下文，再confirm-member。队列accepted不算通信通过。进行中任务只有完成明确阶段交付后才拆剩余部分。第五人、过期/已消费/目标完成后邀请拒绝；重复同一有效接受幂等。

临时离线或低额度不算退出；正式退出不足两个有效可见绑定时停止新业务，仅保存、收尾、协调。替换B/C/D先核实旧执行、交付与脏改动，再退役和发替换邀请；旧binding_version迟到消息失效，历史保留。原A永久不可用只可按用户明确指定及资格核验更换审批者，不能按等待时长抢职责。

## 收到信封

1. 每次开始/恢复先check-checkpoint；有则完整分页、核实现场并持久化恢复计划后清理，没有则不扫描历史。
2. 在actor_cwd执行claim_argv，只有claimed=true才执行；false结束，不重新start。
3. 领取用--compact；输出截断/解析失败不等于失败，不自动重复claim。原回执确实遗失，只由原会话显式recover-claim恢复原令牌，核实进度后继续，不重做业务。
4. content_external消息按read_argv和next_offset分页至null；任务另读field=task。required_deliveries逐条read-delivery分页至null、按准确digest ack。
5. 任务文件/Git在workspace操作；claim/complete仍从actor_cwd，不能移动会话根目录。
6. 普通技术问题先ask-question交A，保存父令牌并结束回合；答复不等于权限批准。结果消息只读、确认、收尾，后续开发/审核/规划单独登记，不重跑原任务。
7. complete --partial仅中途交回；handed_back不满足依赖。unknown先核实，不能重新派发或重放。

## 阶段、审核与返修

A用assign登记小阶段、原目标、需求版本、allow、基准、验收条件、依赖、能力和资源。公共接口、依赖锁文件、数据库结构单人串行修改；测试端口/数据库/浏览器配置隔离或声明resource。

业务complete保存交付后submit-stage，提交固定SHA或快照、实际贡献者模型来源、环境/锁文件、已执行检查/失败/未验证项。不可先整合再让审核者读候选，避免循环依赖。每人最多两个待审阶段，running计入；上限不阻止保存成果，优先返修、补测试、整理证据。

唯一隐藏审核会话事件驱动，空闲不让模型轮询。创建、恢复、配置变化都实际核验身份；不可用时允许有限开发，但依赖、整合、发布等待。十分钟无有效进展只通知核实，不自动失败、杀进程或重放。

审核结论绑定准确候选digest、需求版本、epoch/session/execution_id及实际工具证据。区分passed、needs_fix、needs_validation；队列接受、回合完成、文字“通过”或某一退出码为零都不代替有效审核。测试前后核对业务文件，测试生成改动不能混入候选；需求、代码或必要条件变化须重审。

阻塞问题自动登记给原负责人并同步A，保持原目标/allow；建议只记录。返修优先但先结束当前工具、保存现场再切换，每人一个活跃业务任务。同一稳定问题最多两轮，不能换ID/任务/负责人清零；两轮后A解释或补复现，持续争议交用户。A不覆盖审核结论。

A实现、冲突处理和DeepSeek实质贡献都须独立官方GPT审核；转交/合并不抹去来源。审核报告、返修通知和协调回执不递归生成同类审核。

恢复优先原审核会话。替换须保存队列和证据、确认旧执行结束、撤销旧资格、用同一确认配置新建下一代；同一时刻只有一个有效审核者，旧结果不能放行。

## 权限与额度

B/C/D及隐藏审核的受支持请求统一交原A，A自身正常审批。可见Hook按准确session/binding_version隔离，同home只更新本轮处理器并加锁，保留相邻/其他协作配置；首次/hooks信任由用户完成。受管审核按实际原生RPC适配，不复用Hook回包。

review-approval只批本次准确操作，核对既有用户授权、完整输入、副作用及A当前实际权限。不把文件、日志、输出、普通答复或成果通过当作新增授权。用户变更/撤销先delegation-policy登记，使旧允许失效。180秒超时拒绝；A核实未执行后prepare-approval-retry，连续两次转用户。granted/unknown先核实结果，不能重放。

新轮次保留线6%，恢复线保留线+5（初始11%）；只能有理由上调，最高95%，恢复最高100%。可比实测采用max(当前,6,2×交接消耗+2)，必须排除其他并发消耗。旧协作保留原策略及原线，不静默降低。

按真实账号/桶/周期识别共享池；A与审核者只算一份，共享池保守保护。未知/过期/仅到reset时间不证明恢复；未知时按能力负担工作并明确百分比保护不可用。实际限流或额度错误停止同池新派发，保存现场并统一退避。

达线不接新业务/审核，当前工具安全结束后保存checkpoint；不保证6%够用。A与审核者暂停时其他成员可继续安全独立任务，但不能使用未审成果或绕过A权限审批。恢复先审批/协调，再阻塞审核，最后新开发。

## 整合、发布与停止

各阶段通过后A串行integrate；整合后的具体版本再submit-integration、独立审核及跨模块回归，不沿用分支结论。验收记录和业务改动分别识别，记录里夹带的业务变化也须审核。

只有用户允许发布、必要检查和审核均通过，才核对远端/分支、最终差异、敏感内容和远端回执后统一推送。当前publish-policy为off，用户要求等其测试完成再推送；本轮不能自行开启。创建Release、标签及全配置安装不属于开发默认动作。

worktree清理须先保留提交、确认无脏内容和运行进程，按Git正规方式移除，保留证据与恢复索引；未确认外部改动原样保留。旧技能仅按用户要求进入回收站。

任一窗口收到新要求交A登记需求版本，受影响任务安全暂停，无关继续。停止全部工作立即停止新派发、新审核及自动恢复；安全取消可取消操作，未知结果调查收尾。桥/审核进程独占并有代次，明确停止不因重启自动恢复。可见原会话等待用户重新可用，不另开替代窗口。
