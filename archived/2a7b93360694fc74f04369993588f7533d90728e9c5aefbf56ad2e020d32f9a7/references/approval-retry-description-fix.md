# 审批重试关联修复（2026-10-19）

## 问题与修改

真实双窗口超时测试中，同一 Bash 写入命令第二次请求只改变说明文字，仍被登记为 `attempt=1`、`previous_id=None`，因此未进入连续两次超时的 `needs_user`。原因是操作身份摘要包含整个 `tool_input`，把 `description` 的变化视为执行操作变化。

修复仅对含字符串 `command` 的 Bash 请求，在重试身份匹配时排除 `description`。命令、工作目录、其他执行字段和未知工具字段仍严格参与匹配；完整审批摘要仍包含说明文字，每次仍须独立审核，不复用旧批准。

历史记录按原始事件重新计算匹配身份，限定同成员和授权版本，不改写旧审批状态、令牌、摘要或已记录结果，也不把此前未关联的失败现场改成通过。
